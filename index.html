What is nxtsOS?

nxtsOS is an open-source operating system written from scratch with the help of Muse AI, in C + Assembly. A Linux-like system, but not Linux at all — built to stay lightweight and give users direct control over their own system.

nxtsOS is a complete operating system written from the ground up: its own kernel, its own filesystem, its own shell, its own networking stack — in C and assembly, on 32-bit x86 today, with a 64-bit build on the roadmap.

It is not a Linux distribution and not a Linux fork. It aims to be comparable to Linux in capability — the same everyday tools, services, and security discipline — while remaining its own system, built and verified in the open, one release at a time.

The design is CLI-first: a full command line, real services, and a signed package system come before any graphical desktop. A text interface (TUI) is planned as an optional package, not as part of the core system.

What it can do today (v1.1.6)

Core system

  • Preemptive multitasking, demand paging, and SMP on up to 2 CPUs
  • Virtual filesystem with directories, hard links, and permission-gated traversal
  • Users, groups, sudo, and capability bits — with a real audit trail
  • Shell with jobs, pipes, redirection, scripting, and grouped help

Networking & security

  • Ethernet, DHCP, DNS, TCP sockets and a TCP server
  • HTTPS with TLS 1.3 (plus opt-in legacy TLS for old servers only)
  • Firewall, signed package repository, and system updates with rollback
  • Installer that partitions, formats, and installs the system on disk

Everyday tools

  • Terminal editor, file and text tools, process view, and resource reporting
  • Linux-like layout: /bin, /sbin, /etc, /home, /usr, /var/log, /tmp
  • Service manager with dependencies, supervision, and boot services

Where it is going

Development continues in phases toward v1.1.7, the next release. In order:

  1. Firewall as a telemetry escape (egress allowlist + signed blocklist)
  2. Download tools, a live process monitor, and proper memory-failure reporting
  3. Login sessions, then a 64-bit x86 kernel build
  4. Full-capability utilities, clean release builds, completed packages, flexible resolutions, and complete guides
  5. Date and time management, a TUI package, scheduling and logging
  6. Core, networking, hardware, and security parity with Linux — staged, device by device
  7. Developer parity: archives, an on-OS toolchain, and complete manual pages

No release is cut until its full regression and security checks pass on the final image.

Honest status

nxtsOS is tested under QEMU, with a full regression suite run on every release image. It has not yet been tested on real hardware, and some features are honestly documented as inactive rather than claimed — for example, swap space and real-time scheduler classes are defined but not active, and the mandatory-access-control check is currently an explicit no-op hook, never described as enforcement.

That honesty is part of the project: a feature is only called done when it has actually been verified.
